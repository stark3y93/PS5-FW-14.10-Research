# Prioritized offline research

1. **Obtain target-matched WebKit evidence for the CSSFontFace candidate.** The upstream WebKit fix establishes a real `CSSFontFace::setStatus` use-after-free scenario, but the reviewed fix only proves upstream behavior. Secure an authorized PS5 14.10 WebKit source revision or browser binary/build identifier and compare the corresponding implementation with the fix. A Sony fork may differ or backport it. Until a matching implementation and controlled reproduction are available, keep 14.10 impact unresolved.
2. **Independently validate the public userland execution record.** The external 80j and 80k source/log pairs now contain expected marker readbacks, but remain self-published and lack authenticated device/firmware identity. A separately recorded, authorized test should show firmware identity, source hash, original marker, call result, readback, and scratch restoration, with the raw capture retained. Keep this separate from kernel-exploit testing.
3. **Preserve and normalize local evidence.** Run the evidence audit and retain generated JSON with original logs. For each historical V429/V432/V445 claim, locate the complete session, console model, and test source revision. Treat filename timestamps as unverified labels.
4. **Establish firmware provenance.** Record the official PUP SHA-256; validate package version through trusted Sony metadata. The SLB2 header cannot identify WebKit or kernel patch state. Do not infer contents from encrypted payload sizes.
5. **Re-evaluate MetadataTable offline.** Use synthetic count/stride cases around the exact uint32 boundary and review the immutable upstream source and fix. Do not infer a PS5 heap write from compilation or a lost beacon. Preserve the corrected V480 result with any discussion of earlier runs.
6. **Audit FreeBSD candidates against Sony's fork.** Compare exact patched functions for CVE-2026-7270 and CVE-2026-45251 against an authorized 14.10 kernel artifact, then separately assess syscall reachability. Without both, classify them as upstream-only.
7. **Document chain gaps.** The userland primitive reported by the external project still needs an independently authenticated execution record; separately, the full chain needs a demonstrated browser/app entry, sandbox transition, kernel vulnerability, and kernel read/write. Hypervisor/content-protection impact needs separate evidence. Debug Settings alone does not verify later stages.

These steps are read-only. No live payloads, console changes, or dependency installation are required.

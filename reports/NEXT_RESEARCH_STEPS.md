# Prioritized research after the WebKit source audit

1. **Obtain an exact, authorized 14.10 browser build correspondence.** Sony's published “14.00 -” source has now been inspected and lacks both font safeguards. The highest-value missing item is a vendor component/source mapping or lawfully supplied browser binary with reliable `26.06-14.10.00` provenance. Compare the actual backing-load and client-iteration functions, including possible backports. Repeating the public source comparison cannot establish the executable's patch state.
2. **Run a version-pinned PC engine regression pair when a suitable build environment is available.** Run the public font-face regression under the old and fixed WebKit builds and retain source hashes, build configuration and harness output. A source model or generic browser pass does not substitute for this test. The current synthetic tests establish logical reentrancy/ownership differences only.
3. **Obtain independently authenticated userland result records.** PR #20's 80j/80k captures support reported marker writes; 80i still lacks readback and completion. A separately retained capture with exact source hash, target identity and original/result values would address authenticity. It would not establish a kernel vulnerability.
4. **Keep evidence reproducible.** Preserve the source manifests, primary URLs, member hashes, and the distinction between partial ZIP reads and a full archive digest. Record a new snapshot when upstream/Sony sources change; never overwrite original logs or treat publication dates as build dates.
5. **Keep MetadataTable and kernel candidates gated.** The corrected V480 zero-hit result rebuts that particular string-corruption claim. Other MetadataTable mechanisms still need exact target code and an independently explained memory fault. FreeBSD CVEs need Sony-fork function matching and reachability evidence; upstream advisory ranges cannot be applied directly to 14.10.
6. **Keep source defaults and runtime configuration distinct.** Sony's published JIT/DFG/FTL defaults are OFF, making JIT-only hypotheses less promising. Production overrides and enabled components remain unknown. User-agent and feature fingerprints cannot settle those flags or engine revision.

The same source diffs now have diminishing research value unless new evidence changes them. The current milestone is a verified source lead, with an **UNKNOWN** exact-firmware verdict. No live console operation, exploitation, dependency installation or firmware access bypass is part of this offline workflow.

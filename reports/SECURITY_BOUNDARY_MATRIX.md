# PS5 14.10 security boundary matrix

Audit: 20 October 2026. These are separate capabilities; a kernel bug reachable from a sandbox may cross multiple boundaries at once. This table is an evidence checklist, not a universal required exploit design.

| Stage | Public evidence | What this repository establishes | Unproven for this 14.10 console | Safe uncertainty-reducing experiment | Breakthrough evidence |
|---|---|---|---|---|---|
| Browser entry / page JavaScript | [Sony's guide documentation](https://www.playstation.com/en-us/support/hardware/ps5-console-users-guide/) confirms guide navigation, not arbitrary URLs. | User reports the guide opens. New diagnostic is passive; PC preview and synthetic fixtures tested. | External-page navigation and the actual console's API results. | Photograph guide context; if an ordinary route already permits the diagnostic URL, record its passive summary. | Retained page/version/context record showing the audited page completes on the identified console. This is page execution only. |
| Native userland execution | External source-matched 80j/80k captures at [audited commit](https://github.com/ZigZagBoi1/PS5-14.10-Research/tree/9c89819cf74002b616108bd674b398ae919b40b6); earlier game/Lua context differs from the guide browser. | [PR #20 audit](EXTERNAL_THREAD_ROP_AUDIT.md) supports expected user-memory marker changes in self-published logs. | Independent device/firmware authentication and reproduction; a guide-browser native primitive. 80i still has no readback. | Review original source/context and capture provenance offline. | Independent authenticated source-hashed recording with pre-state, invocation, result, readback and cleanup; no such new execution requested here. |
| Browser sandbox | Older public [UMTX project](https://github.com/PS5Dev/PS5-UMTX-Jailbreak/tree/2cf6778ebe89ff35255e1c228826d0d2155e9d2a) describes sandbox/root changes after kernel access. | No 14.10 process credential, jail, broker policy or sandbox transition verified. | Which native interfaces this guide process can reach, and whether a separate sandbox escape is required. | Study authorized build/process policy records offline. | Target-specific before/after security context and attributable boundary crossing; ordinary API support is insufficient. |
| Kernel privilege / data access | Same older project exposes kernel data R/W while documenting further limits; Gezine's 14.10 Debug Settings report lacks a disclosed reproducible method in our audit. | No verified 14.10 kernel flaw, kernel R/W or kernel execution. | Vulnerable target code, reachability, reliable primitive and privilege change. | Compare exact patched functions against authorized target-matched material. | Independently explained/repeated kernel-state evidence tied to exact firmware and source. User-space writes and zero syscall return do not qualify. |
| Hypervisor / protected kernel code | [Original Byepervisor](https://github.com/PS5Dev/Byepervisor/tree/57204cbd7bd26ed4623634d52b0f60f40d630087) and [Reborn](https://github.com/PS5Dev/Byepervisor-Reborn/tree/ea04f7132b837087f552c57261cb800481a3a910) publish different older-firmware work. | Reborn's claimed range and prerequisites were recorded, not executed. | 14.10 compatibility, protected code visibility and any HV transition. | Check version-specific public support and authorized build/patch records. | Authenticated target proof of the particular protected operation. HV compromise is not established merely by Debug Settings and is not proven necessary for that menu. |
| Firmware correspondence | Sony maps a source bundle to the 14.xx family; fresh sampling shows both old code and selective validation backports. | Exact source hashes and pinned upstream comparisons. | Exact production executable linkage and production build flags. | Obtain vendor correspondence or a lawfully supplied artifact with reliable firmware provenance. | Signed/trusted build-to-component mapping plus exact relevant-function comparison. |
| Reproducibility | Public source and self-published captures exist for some prior stages. | Offline tooling/tests and evidence hashes reproduce analysis only. | Independent 14.10 hardware result and complete chain. | Retain originals, source hashes, full sessions and failures; distinguish transcription from raw capture. | A separately reproduced, context-authenticated result with all relevant postconditions. |

Kernel data R/W, kernel instruction execution, protected kernel text modification and hypervisor access are distinct results. XOM, page protections and CFI are documented constraints in older public work; their exact 14.10 configuration is not verified here. Firmware numbers or offsets cannot be carried forward as proof. The non-browser Lua record cannot be silently attached to a WebKit entry hypothesis.

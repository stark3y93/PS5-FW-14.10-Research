# Phase 4 implementation plan

**Goal:** collect harmless browser observations and separate them from evidence of native execution and privileged access.

**Architecture:** a static, dependency-free page exports a bounded JSON capability record. A standard-library importer validates records, retains file hashes and JSON pointers, compares only matching firmware labels, and produces a conservative boundary matrix. Existing source-version comparison remains the pinned WebKit tool from PR #21.

**Constraints:** no exploit code, console operation, dependencies, telemetry, firmware publication, force push or merge. Continue inline under the user's explicit autonomous execution instruction. Base: `f650adecbd4e08a2f00da8615c17d99b5485df6c`; preserve PRs #20/#21.

## Review focus

- A purported VERIFIED kernel claim in diagnostic JSON must be rejected.
- Different firmware labels and incomplete captures must not produce capability contradictions.
- Hostile strings must remain text in the page and escaped in Markdown.
- JSON sizes, nesting, types and duplicate keys must fail closed.
- Missing APIs or restricted getters must not abort the page's remaining checks.

# Sony source validation, 2026-10-20

## Scope and provenance

This phase uses only Sony's public [WebKit](https://www.playstation.com/en-us/oss/ps5/webkit/) and [JavaScriptCore](https://www.playstation.com/en-us/oss/ps5/webkit-javascriptcore/) archives and the [upstream WebKit commit b21a503](https://github.com/WebKit/WebKit/commit/b21a503b579a8ab14c839f82cc77176e507352e5). Apple identifies the same WebKit Bugzilla item, 302502, in its [CVE-2025-43529 advisory](https://support.apple.com/en-us/125884). Apple's affected-product statement does not transfer to PS5.

The two complete ZIPs are retained locally under ignored `artifacts/sony-oss/`; their URLs, sizes, SHA-256 digests, entry counts and source markers are in [source-archive-analysis-2026-10-20.json](source-archive-analysis-2026-10-20.json). Reproduce that report with `python -S research/source-validation/analyze_archives.py`. No source archive or Sony code is committed.

Sony labels WebKit `14.00 -` and JavaScriptCore `8.00 -`. The WebKit archive declares `616.1.27.211.1` in `Configurations/Version.xcconfig`; the JSC archive's `Source/JavaScriptCore/ChangeLog` starts 2022-03-25. Neither marker independently identifies build `26.06-14.10.00`, a Git commit, the exact compiled binary, or enabled DFG settings. The ZIP HTTP modification dates are publication metadata, not source revision dates.

## Patch comparison and limits

The [pinned file map](upstream-file-map-2026-10-20.json) compares seven independently selected Sony WebKit ZIP members with upstream WebKit tag `WebKit-7616.1.27.211.1`, peeled commit `0e722583a4d695c7b25f384c61fbf5b59b4c3146` (2023-09-15). Four files are byte-identical: `Configurations/Version.xcconfig` (`2c2f5d80…`), `DFGStoreBarrierInsertionPhase.cpp` (`68862b10…`), `DFGPhiChildren.h` (`76e87af4…`), and `WTF/wtf/Vector.h` (`5995bf85…`). Three sampled files differ: `WebCore/dom/Document.cpp`, `WebKit/WebProcess/WebPage/WebPage.cpp`, and `Source/cmake/OptionsPlayStation.cmake`. This pins lineage for selected files while proving the archive contains Sony changes. It does not date every file or identify a compiled 14.10 binary.

[Upstream b21a503](https://github.com/WebKit/WebKit/commit/b21a503b579a8ab14c839f82cc77176e507352e5) modifies only `DFGStoreBarrierInsertionPhase.cpp` (+13/−7 lines) relative to parent `1348ad620797f30b9916bbd40423969fa4a8c1cd`. It introduces a phase-level `escape` helper that, in global mode, traverses `m_interpreter->phiChildren()->forAllTransitiveIncomingValues` before setting epochs. It applies that helper to a potential stack escape and a final pending escape as well as the existing write handling. The upstream commit message explains a missed store barrier when a Phi escapes but an incoming value is used directly later; Apple maps the same Bugzilla 302502 to CVE-2025-43529 for its named products. The commit contains no test file. Sony's byte-matched 2023 phase retains direct marking at those sites; its `DFGPhiChildren.h` already provides the traversal helper and `DFGAbstractInterpreter.h` provides `phiChildren()`. A bounded JSC search found helper references in four files, none in the Sony store-barrier phase. [Machine-readable audit](b21a503-context-2026-10-20.json).

**Security relevance is conditional and presently low for the published PlayStation defaults.** Sony's modified `OptionsPlayStation.cmake:206-208` sets `ENABLE_JIT`, `ENABLE_FTL_JIT` and `ENABLE_DFG_JIT` OFF by default; the phase is inside `#if ENABLE(DFG_JIT)` at line 29. `WebKitFeatures.cmake` makes DFG depend on JIT and FTL depend on DFG. A targeted scan of CMake/source metadata found no explicit DFG ON override, but CMake cache options or unpublished production settings could override defaults. Therefore the source difference is a genuine upstream security fix delta in a named file, but it is **not demonstrated as an active Sony PlayStation defect**. Exact PS5 14.10 build flags, component identity and any equivalent fix outside the inspected phase remain unverified. The older `JSC-800.zip` also lacks the call, but its different function structure prevents treating it as an exact pre-patch match.

The existing [WebKitGTK advisory](https://webkitgtk.org/security/WSA-2026-0004.html) and 14.10 community reports remain upstream or author claims in the knowledge base. This phase did not find a commit-to-Sony-source match for their named CVEs, so no product finding was promoted from those records.

## Strongest next PC-only experiment

Seek an authenticated Sony 14.10 build manifest or public build configuration that establishes the compiled JavaScriptCore revision and effective `ENABLE_DFG_JIT` setting. That is the highest-value next experiment because a PC engine reproduction cannot establish relevance while the published PlayStation port defaults DFG off. A full, unmodified JSC build with required host dependencies and sanitizers could later test upstream engine behavior, but would still be engine-level evidence only. The broader homebrew goal, including compatible applications and Steam games, remains outside what this source audit can establish.
